# Northfield Student Management Portal

A React and TypeScript portal for student coursework and administrator operations. FastAPI exposes the REST API, SQLAlchemy handles persistence, and Alembic owns the SQLite schema.

## Local setup

Use Python 3.11+ and Node.js 22.12+ (or Node.js 24). Run these from the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements-dev.txt
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Set `JWT_SECRET` in the local `.env` to the randomly generated value. The sample file defines the local origins and database path. Bash users can activate with `source .venv/bin/activate` and copy with `cp .env.example .env`.

For a populated local workspace, set `DEMO_ADMIN_EMAIL`, `DEMO_STUDENT_EMAIL`, and independent random passwords of 12–128 characters in `.env`. Use the configured email and password pairs to sign in. The seed creates 1 administrator, 18 students, 12 courses, 72 enrollments, 24 assignments, 54 submissions, and 126 sample activity events. Repeated executions retain existing data. In development, the synthetic student accounts share the configured demo student password.

```powershell
cd backend
python -m alembic upgrade head
python -m app.seed
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers --no-access-log
```

In a second terminal, from the repository root:

```powershell
cd frontend
npm ci
npm run dev
```

Open [the portal](http://127.0.0.1:5173). Vite proxies API calls to port 8000. Use the same host name consistently, since cookies are host-scoped. The [API reference](http://127.0.0.1:8000/docs) is available in development. Run `npm run build` and restart FastAPI to serve the compiled SPA at [port 8000](http://127.0.0.1:8000).

For a database without demo users, skip the seed. Register a student from the UI. After applying migrations, an operator can provision an administrator with an interactive password prompt:

```text
python -m app.admin --email operator@example.com --name "Portal Operator" --account-id ADMIN-001
```

## Structure and data

| Path | Purpose |
| --- | --- |
| `frontend/src/pages/`, `layouts/`, `components/` | Dashboard, courses, assignments, profile, settings, activity, and student administration |
| `frontend/src/api.ts`, `context.tsx`, `hooks.ts` | Axios requests, session and theme state, loading and refresh |
| `backend/app/` | FastAPI application factory, API routers, validation, models, session policy, and request boundary |
| `backend/alembic/`, `backend/tests/` | Versioned schema and tests that migrate isolated SQLite databases |
| `Dockerfile` | Builds the SPA and packages it with the API |

| Table | Purpose |
| --- | --- |
| `users` | Case-normalized unique email and student ID, Argon2id hash, role, and profile |
| `courses` | Catalog entries, instructors, durations, and enrollment status |
| `enrollments` | Unique student–course pairs, progress, completion, and last access |
| `assignments` | Course-linked instructions and UTC deadline |
| `submissions` | Text revisions linked to a student and an assignment |
| `activity_logs` | Structured, correlated application events |
| `sessions` | Revocable JWT session identifiers and expiration |

SQLite enables foreign key enforcement and WAL. The database lives at `SQLITE_PATH` and is generated by migrations. Closing a course stops new enrollment. Deleting a course also deletes its enrollments, assignments, and submissions. Assignment revisions remain available in submission history while the assignment exists.

## API reference

| Methods and paths | Access |
| --- | --- |
| `POST /api/auth/register`, `POST /api/auth/login` | Public, rate-limited |
| `GET /api/auth/me`, `POST /api/auth/logout` | Signed-in user |
| `GET /api/dashboard/stats`, `GET /api/dashboard/activity` | Role-scoped |
| `GET /api/courses`, `GET /api/courses/{id}` | Signed-in user |
| `GET /api/courses/enrolled`, `POST /api/courses/{id}/enroll`, `POST /api/courses/{id}/access`, `PUT /api/courses/{id}/progress` | Student's own enrollments |
| `POST /api/courses`, `PUT /api/courses/{id}`, `DELETE /api/courses/{id}` | Administrator |
| `GET /api/assignments`, `GET /api/assignments/{id}`, `GET /api/assignments/{id}/submissions` | Enrollment and ownership scoped for students, all for administrators |
| `POST /api/assignments/{id}/submit` | Enrolled student before deadline |
| `POST /api/assignments`, `PUT /api/assignments/{id}` | Administrator |
| `GET /api/students/me`, `PUT /api/students/me` | Own profile |
| `GET /api/students` | Administrator |
| `GET /api/activity` | Own activity for students, application records for administrators |
| `GET /health` | Public SQLite schema readiness probe |

Login, registration, and `/api/auth/me` return the user and a session-specific CSRF token. Mutating authenticated requests send it in `X-CSRF-Token`. The browser keeps the JWT in an HttpOnly cookie with the `Secure` flag and `__Host-` prefix in production. The default is `SameSite=Lax`. Separate Render domains use a partitioned `SameSite=None` cookie. The SPA keeps its CSRF token in memory. Logout revokes the session on the server. Courses accept `search`, `category`, `sort`, `page`, and `page_size`. Activity, student listings, and submission history accept `offset` and `limit`.

## Deploy to Render Free

Use a Hobby workspace without a linked payment method to prevent build or bandwidth overage charges. Render pauses builds or suspends services when the corresponding included quota runs out. The Free API can spin down after 15 minutes idle. Render can discard SQLite on spin-down, restart, or redeploy, including sign-ups, edits, submissions, and sessions. Use synthetic data throughout. [Render free limits](https://render.com/docs/free) · [Render billing FAQ](https://render.com/docs/faq#all-of-my-services-run-on-free-instances-can-i-still-be-billed)

### Blueprint

1. Push the source and root `render.yaml` to a Git repository you can connect to Render. Keep `.env`, database files, and local build artifacts out of the repository.
2. In the Render Dashboard choose **New → Blueprint**, connect that repository, select the branch, and use `render.yaml`. Review the proposed services before deploying. The Blueprint defines one Free Python Web Service and one Static Site, with automatic deploys and previews disabled.
3. Fill in the prompted frontend API URL, backend allowlist, and demo account values from the table below. The default service names suggest `https://northfield-portal-api.onrender.com/api` and `https://northfield-portal.onrender.com`. These are examples. Compare them with the actual assigned service URLs after creation and update the Environment pages if either differs. Rebuild the frontend after changing its API URL and restart the API after changing its allowlist.
4. Verify the API's deployed `/health` returns `{"status":"ok"}`. Open the Static Site and run the checks below. [Render Blueprint setup](https://render.com/docs/infrastructure-as-code)

### Manual dashboard settings

If setting up services individually, first create **New → Web Service** and choose the **Free** instance type. Create **New → Static Site** from the same repository and branch. Set each service's auto-deploy option to **Off**. Use the table below. In the Static Site's **Redirects/Rewrites**, add a **Rewrite** from `/*` to `/index.html`. Apply the three static response headers from `render.yaml` with path `/*`. Copy the assigned hostname from each service's overview and use the matching environment values. For the first API deploy, you can use the expected Static Site origin and correct it once Render assigns both URLs. [Render monorepos](https://render.com/docs/monorepo-support) · [Static Site rewrites](https://render.com/docs/redirects-rewrites)

| Setting | Static Site | Free Web Service |
| --- | --- | --- |
| Root Directory | `frontend` | `backend` |
| Runtime | Static Site | Python |
| Build Command | `npm ci --include=dev && npm run build` | `python -m pip install -r requirements.txt` |
| Publish Directory / Health Check Path | `dist` | `/health` |

Set the **Web Service Start Command** to:

```sh
python -m app.bootstrap && exec python -m uvicorn app.main:create_app --factory --host 0.0.0.0 --port "$PORT" --workers 1 --no-proxy-headers --no-access-log --no-server-header
```

| Service | Variable | Value |
| --- | --- | --- |
| Static Site | `NODE_VERSION` | `24.22.1` |
| Static Site | `VITE_API_BASE_URL` | The API's assigned HTTPS origin with `/api` appended |
| API | `PYTHON_VERSION` | `3.14.10` |
| API | `APP_ENV` | `production` |
| API | `SQLITE_PATH` | `/tmp/northfield/portal.sqlite3` |
| API | `JWT_SECRET` | Render generates this for the Blueprint. For manual setup, set a fresh secret with `python -c "import secrets; print(secrets.token_urlsafe(48))"`. |
| API | `ALLOWED_ORIGINS` | The Static Site's assigned HTTPS origin, with no path. Use commas for multiple explicitly trusted origins. |
| API | `SESSION_CROSS_SITE` | `true` |
| API | `SEED_DEMO_DATA` | `true` |
| API | `DEMO_ADMIN_EMAIL`, `DEMO_STUDENT_EMAIL` | Two distinct synthetic addresses, e.g. `portal-admin@example.com` and `portal-student@example.com` |
| API | `DEMO_ADMIN_PASSWORD`, `DEMO_STUDENT_PASSWORD` | Generate each separately with `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Keep both in API settings. |

Render supplies `PORT`. Set secrets in the API environment only. The frontend bundles its public API URL at build time. Use one Uvicorn worker with SQLite. The original Dockerfile is available for same-origin self-hosting.

### Initialization, sessions, and verification

- Startup runs an Alembic upgrade inside an explicit SQLite transaction and seeds demo data once per database. Seeding is transactional, retains an initialized database, and rebuilds the synthetic dataset when the file disappears. The 17 additional demo students receive independent, undisclosed random passwords on Render. Seed credentials apply at first initialization. Changing a password environment variable does not rotate an existing account.
- Axios sends credentialed requests. The API checks the exact frontend origin and requires a CSRF token for authenticated writes. The session cookie is host-only, `Secure`, `HttpOnly`, and `SameSite=None; Partitioned`. Use a current browser with partitioned-cookie support. Local development keeps the same-origin proxy and `SameSite=Lax`. [Browser partitioned cookies](https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies/Partitioned_cookies)
- Verify the Static Site opens and a direct visit to `/courses` resolves through the SPA rewrite. Register a synthetic student, sign in, reload the dashboard, enroll in a course, submit an upcoming assignment, edit the profile, and sign out. Sign in as the configured demo administrator and verify the student roster and submissions. Check the browser's network panel for the expected API host, exact CORS origin, cookie flags, and protected-route responses. Confirm the frontend assets contain only the public API URL and review startup logs for the schema and seed status.
- For a slow first request, allow the Free API to wake up and retry. For a CORS error, compare the browser's exact page origin with `ALLOWED_ORIGINS`. For a login that disappears on reload, inspect the cookie attributes and browser cookie settings. For a startup error, check the Python version, `SQLITE_PATH`, and distinct demo credentials. A fresh frontend build is required after changing `VITE_API_BASE_URL`.

`API_PROXY_TARGET` controls the local Vite upstream. The default start command ignores forwarded headers, so clients behind the same proxy may share the per-peer authentication rate limit. For a future trusted gateway, configure `--proxy-headers --forwarded-allow-ips <trusted-proxy-addresses>` after verifying that the proxy sanitizes the forwarding chain.

## Future cybersecurity integration

- `backend/app/middleware.py` generates a correlation ID, returns it as `X-Request-ID`, and sets request context for timings, response status, body byte counts, and access decisions. An ASGI middleware can use that context and the matched route template for payload-free telemetry. Group unmatched paths under a fixed label.
- `backend/app/activity.py` centralizes structured event creation. It inserts events in the same transaction as business changes. A future asynchronous exporter can read committed events using their IDs as delivery keys.
- Keep auth and validation outcomes in request context and exclude passwords, cookies, JWTs, CSRF tokens, submission text, and raw request bodies from exported telemetry.
- The API base and trusted proxy settings support a future security gateway. Feed the external GATv2 system compatible network-flow features or use a separately validated telemetry model.
## Optional request telemetry

The backend can forward structured HTTP completion metadata to a Sentinel Stage 1 collector. Set all three variables to enable it.

| Variable | Example |
| --- | --- |
| `TELEMETRY_COLLECTOR_URL` | `https://telemetry.example.com/v1/http-events` |
| `TELEMETRY_APP_ID` | `northfield-prod` |
| `TELEMETRY_HMAC_KEY` | The collector's matching per-app 64-character lowercase hex key |

Production requires HTTPS. For local development and tests, a loopback HTTP collector is supported. The sender uses an in-memory queue. It forwards request IDs, route templates, methods, statuses, durations, and enumerated authentication outcomes. Keep the key in the backend environment.
